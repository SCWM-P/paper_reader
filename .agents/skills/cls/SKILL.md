# Controled Language Style

本 skill 规定 Agent 面向用户阅读的一切资料的风格与规定。依据是 ASD-STE100 的写作原则。确保**输出必须只有一种读法，关键信息一眼可见**。
本 skill 不是 ASD-STE100 标准本身，也不复述标准原文。ASD-STE100 只规定英文。
本 skill 吸纳 ASD-STE100 的原则并改写为中文规则。更多关键词的固定译法见 [references/terminology.md](references/terminology.md)。

## Skill 生效与失效

### 生效

- 所有会话中面向用户的交流都必须遵守本 skill ，加载本 skill 起**即刻生效**。
- 生效时，必须打印这样一条信息 "[INFO] ｜ **Controled Language Style Enabled**"
- 生效时，必须读 [references/terminology.md](references/terminology.md) 的第 2–4 节。
- 同优先级风格规则 (同级 Skill 语言风格规范) 冲突且用户未明确指定风格时，优先遵循本 skill。 

### 失效

- 会话中用户明确指定其他格式或风格时，优先使用指定的格式或风格，本 skill 即**失效**。
- 失效时，请打印这样一条信息 "[INFO] ｜ **Controled Language Style Disabled**"

## 输出语言

- 默认优先使用简体中文。
- 用户指定其他语言，或项目规定了输出语言时，用指定的语言。
- 输出语言是英文时，按 ASD-STE100 的原则写英文：步骤句不超过 20 个词，描述句不超过 25 个词。R1–R6 六组中与语言无关的规则照常适用。

## 写作规则

### R1 词

- **R1-1 一词一义。** 一个词在全文只表示一个意思。一个意思在全文只用一个词。优先采用用户使用的词。例：选了「任务」，就不再写「卡」「工单」「ticket」。
- **R1-2 先定义，后使用。** llm-wiki 收录用户学过的专业名词与共识概念。用户已知的词语或概念不定义。只有一两个专用词时，可以在首次出现处用括号定义。
- **R1-3 用具体动词。** 不用虚化动词包装动作。写「修改配置」，不写「对配置进行修改」。完整清单与替换写法见 [references/terminology.md](references/terminology.md) 第 3 节。
- **R1-4 字面量保持原样。** 界面文案、按钮名、代码标识符、命令、路径保持原文。代码、命令、路径写在反引号内。
- **R1-5 名词串不超过 3 个名词。** 「终端会话失败反馈界面状态」必须拆开写：「终端会话失败时的界面状态」。

### R2 句

- **R2-1 一句一事。** 一句只写一个动作或一个事实。两个动作写成两句。
- **R2-2 句长上限。** 步骤句不超过 50 字。描述句不超过 75 字。计数方法：一个汉字计 1 字；一个英文单词、数字或代码标识符计 1 字；标点不计。
- **R2-3 用主动语态。** 写出谁做动作。不用「被」字句，除非执行者不明确或不重要。
- **R2-4 条件在前，动作在后。** 写「连接失败时，显示错误。」不写「显示错误，如果连接失败的话。」
- **R2-5 不用双重否定。** 写「必须确认」，不写「不能不确认」。
- **R2-6 情态词固定词义。** 只用「必须」「不得」「可以」。见 [references/terminology.md](references/terminology.md) 第 2 节。
- **R2-7 主语明确。** 主语省略后有两种读法时，补出主语。

### R3 段落

- **R3-1 一段一个主题。** 一段不超过 6 句。
- **R3-2 步骤用祈使句。** 步骤用编号列表。每步一个动作。动作的结果写在下一句。
- **R3-3 列表代替长句。** 五个以上并列项写成列表，不用顿号连成长句。
- **R3-4 不写开放式列举。** 不用「等」「之类」结束列举。列全，或写出完整清单的位置。
- **R3-5 谨慎否定转折。** 禁止无端转折。禁止随意插入否定词。禁止突兀地混排肯定句和否定句。谨慎使用这些**转折词**：

### R4 汇报

- **R4-1 关键信息先行。** 首句内容按回复类型确定。进度说明写当前动作与对象；结果汇报写状态与完成范围；排查结论写原因或「原因未确认」；请求决定写待决事项；多项总结写总体结论或总结范围。普通解释或建议先写核心答复，不强套模板。细节和证据写在后面。
- **R4-2 状态词固定。** 写工作状态时，只用以下 10 个状态词：已完成、部分完成、未开始、进行中、已验证、未验证、失败、跳过、阻塞、未确认。状态必须对应明确的工作或检查范围。工作状态不代替验证状态。词义和完成条件以 [references/terminology.md](references/terminology.md) 第 4 节为准。不得用「已」加其他动词代替状态词。写「已完成：登录刷新逻辑的代码修改」，不写「已修改登录刷新逻辑」。
- **R4-3 不叙述过程。** 不写「我先……然后……接着……」。直接写用户需要的关键信息与证据。
- **R4-4 证据可定位。** 引用代码写 `路径:行号`。引用提交写提交号。引用命令写完整命令。
- **R4-5 不确定时写明。** 没有确认的事实，标「未确认」，并写出确认方法。不得用「可能」「大概」「应该是」掩盖不确定。
- **R4-6 禁止编造。** 每个事实必须能在来源中找到。来源是用户的输入、文件内容和工具输出。来源没有的内容，不得自行补充。缺少的内容列入「待确认」。

### R5 字符
- **R5-1 中文全角** 中文正文用全角标点：「，。；：（）」。
- **R5-2 直角引号** 引用文案或强调词语用直角引号「」。
- **R5-3 数学符号** 变量、公式、短算式等数学词汇必须使用 $\LaTeX$，即使只有单字符变量。

### R6 格式
- **R6-1 混排锁进** 中文与英文单词、数字之间加一个半角空格。中文与全角标点之间不加空格。
- **R6-2 Code格式** 代码、命令、路径、标识符写在反引号内，内部保持半角。

## 自检清单

每条回复发出前，请检查以下内容。

- [ ] 首句写当前回复的关键信息（R4-1）。
- [ ] 写状态时，使用 R4-2 的固定词，并明确范围（R4-2）。
- [ ] 没有过程叙述（R4-3）。
- [ ] 每个专用词在全文只有一个写法（R1-1）。
- [ ] 没有虚化动词（R1-3）。
- [ ] 每句只有一个动作或事实（R2-1）。
- [ ] 步骤句不超过 50 字，描述句不超过 75 字（R2-2）。
- [ ] 条件都写在动作前面（R2-4）。
- [ ] 情态词只用「必须」「不得」「可以」（R2-6）。
- [ ] 没有用「等」或「之类」结束的列举（R3-4）。
- [ ] 没有「可能」「大概」「应该是」掩盖的不确定（R4-5）。
- [ ] 缺少证据的事实标「未确认」，并写明确认方法（R4-5）。
